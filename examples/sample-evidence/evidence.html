Verify this yourself

This page is a summary, not the evidence. It carries no cryptography and anyone can edit it. The evidence is the JSON bundle this report was generated from. To check it independently, without trusting whoever operates this system and without a network connection, run the open-source Lacre verifier, lacre-verify (package @lacre/verifier), on that file: 

lacre-verify bundle.json --trust <authority-root.pem>

<authority-root.pem> is the timestamp authority's root certificate, obtained from the authority itself and never taken from the bundle. For DigiCert it is DigiCert Trusted Root G4, which DigiCert publishes on its own site. To run the verifier from a source checkout, follow the steps in https://github.com/JaredKlopstein/lacre/blob/main/docs/getting-started.md. Someone technical you trust can run it for you; ask them for the full output.

The verifier is MIT licensed, makes no network connections, and shares no code with the software that produced this bundle. It re-derives every hash and re-checks every signature from the bundle contents alone.

What this does and does not establish

  • It establishes that the receipts in the bundle are internally consistent and were signed by the agent public keys included in this bundle. Those keys come from the bundle itself: nothing here ties a key to a particular system, person or organization, so ask the producer to show you, separately, which system holds each key.
  • It does not yet establish that the history is unaltered. A timestamp token is present and cryptographically sound, but the authority that signed it is not in your trust list, so nothing here rules out that the signer was chosen by whoever produced this bundle. Get the authority's root certificate from the authority itself and run the verifier again with --trust.
  • It does not establish that the actions happened as recorded, or that every action was recorded. Receipts are what the agents chose to record about themselves.
  • It does not make anyone compliant with any regulation. Lacre produces tamper-evident records that support logging obligations. This is not legal advice.
